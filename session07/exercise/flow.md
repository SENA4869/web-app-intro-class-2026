# 実習: リクエスト/レスポンスの流れを書いてみよう

TODO アプリで「新しい TODO を追加する」とき、ブラウザとサーバーの間で
何が起きているのかを順序立てて書いてみましょう。

コードを読むだけではなく、自分の言葉で説明することで
「フロントエンド」「バックエンド」「データベース」の役割分担が見えてきます。

---

## シナリオ

> ユーザーがブラウザ上で「牛乳を買う」と入力して**追加**ボタンを押した。
> 画面のリストに「牛乳を買う」が表示された。
>
> このとき、ブラウザとサーバーの間では何が起きている？

---

## 書き方のヒント

以下の登場人物を使って、「誰が」「何を」「どこへ」するのかを意識して書きましょう。

- **ブラウザ**（HTML / CSS / JavaScript が動く場所）
  - `static/app.js` の関数
  - `fetch()`
- **サーバー**（FastAPI = `main.py` が動く場所）
  - `@app.post("/todos")` のエンドポイント
- **データベース**（`todo.db`）
  - `INSERT INTO todos ...`

---

## あなたが埋める欄

以下の箇条書きを、**10 ステップくらい**で埋めてみましょう。

- ユーザーがブラウザ上で「牛乳を買う」と入力して追加ボタンを押す
- 【ブラウザ】JavaScriptがボタンのクリックイベントを検知する
- 【ブラウザ】`fetch()` を使って、サーバーにデータを送る準備をする
- 【ブラウザ】メソッド `POST`、URL `/api/todos` でサーバーにリクエストを送信する
- 【サーバー】ブラウザからの `POST` リクエストを受け取る
- 【サーバー】データベース（SQLite）に対して `INSERT` 文を実行し、「牛乳を買う」を保存する
- 【サーバー】保存が成功したら、成功ステータス（200 OK など）と追加されたデータをレスポンスとして返す
- 【ブラウザ】サーバーからのレスポンス（JSONデータ）を `fetch()` の続きで受け取る
- 【ブラウザ】JavaScriptでレスポンスからデータを取り出す
- 【ブラウザ】DOM操作（`appendChild` など）を使って、HTMLのリストに新しい要素を追加する
- 画面のリストに「牛乳を買う」が表示される
